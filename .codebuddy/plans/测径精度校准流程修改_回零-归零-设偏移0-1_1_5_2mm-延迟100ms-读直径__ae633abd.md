## 产品概述

修改 U1 治具的测径精度校准流程（CMD 0x0011），将现有"U4 归零→电机 CW 增量移动→判定误差"的流程，改为"电机回零→传感器归零→设置偏移0→移动→延迟→读直径"的新闭环，并保留误差判定与 25B 汇总返回。

## 核心功能

- 新流程：电机回零（U7 0x29）→ 传感器归零（U4 0x10）→ 设置偏移值为 0（U4 0x17）→ 移动电机到 1mm → 延迟 100ms → 读直径 → 移动电机到 1.5mm → 延迟 100ms → 读直径 → 移动电机到 2mm → 延迟 100ms → 读直径
- 移动方向：回零后电机位于 CW 限位端点（IN1），所有移动用 CCW 进入行程区（符合 2026-08-22 已确认经验，避免顶限位失步）
- 定位方式：增量累计定位（1mm=206步，1.5mm 再走 +104步，2mm 再走 +103步，电机不回零点连续走）
- 判定逻辑：每位置按 |Dactual−N|≤50um 判定 PASS/FAIL，汇总返回 25B ACK（格式与旧流程一致）
- 读值方式：移动到位并延迟 100ms 后，等一帧新报文（u4_report_fresh）再读 length，确保取到移动后的新值
- 命令本身 CMD 0x0011（LEN=0）不变，仅内部流程编排变化

## 技术栈

- 平台：STM32F103C6 嵌入式固件（MDK-ARM，C90，Flash 32KB 极紧）
- 协议：U1↔U4（MODBUS 小端 CRC，U4_Proto_Run 非阻塞）、U1↔U7（U7_Proto_Run 非阻塞）
- 状态机模式：非阻塞 phase 状态机，由 APP_Run 主循环周期调用推进（与现有 diam_calib.c / adc_calib.c 一致）

## 实现方案

### 整体思路

复用现有 `diam_calib.c` 的非阻塞状态机架构，重写其流程编排：新增"电机回零"和"设置偏移0"两个前置阶段，将移动方向由 CW 改为 CCW，并引入"移动到位动态等待 → 100ms 稳定延迟 → 等新报文读直径"的三段式取数，判定与 25B 汇总逻辑完全保留。

### 新状态机设计（diam_calib.c 重写）

```
Phase 枚举: DC_IDLE=0, DC_HOME, DC_ZERO, DC_SETOFFSET, DC_MOVE,
            DC_WAIT_MOVE, DC_DELAY, DC_READ, DC_NEXT, DC_DONE
```

- **DC_HOME**：调用 `U7_Home()`（非阻塞，timeout 8s）；成功→DC_ZERO，失败→DC_DONE(全部 FAIL)。
- **DC_ZERO**：调用 `U4_ZeroSensor()`（0x10，非阻塞）；成功→DC_SETOFFSET。
- **DC_SETOFFSET**：调用 `U4_SetOffset(0)`（0x17，非阻塞，tx=[0,0]）；成功→DC_MOVE。
- **DC_MOVE**：增量移动，用 `U7_MotorStep(MOTOR_ID, U7_MOTOR_CCW, delta_steps)`（CCW 进入行程区）。delta 计算沿用旧逻辑：位置0=StepsFor(1000)，位置1=StepsFor(1500)−StepsFor(1000)，位置2=StepsFor(2000)−StepsFor(1500)。指令发出→动态等待 `deadline = 500ms + steps×2ms`（参照已验证的 MotorSeq_Run 公式）→ DC_WAIT_MOVE。
- **DC_WAIT_MOVE**：等电机物理走完（动态等待到期）→ DC_DELAY。
- **DC_DELAY**：延迟 `DIAM_CALIB_READ_DELAY_MS=100ms`（用户要求）→ DC_READ。
- **DC_READ**：置 `u4_report_fresh=0`，等新报文（超时 `DUT_TIMEOUT_MS=1000ms`）；取 `length` 为 Dactual，判定 `|Dactual-N|≤50um` → DC_NEXT。
- **DC_NEXT**：pos_idx++；未完成→DC_MOVE，完成→DC_DONE。
- **DC_DONE**：25B 汇总 ACK（`result[0]=allpass?1:0` + 3×[1B编号][2B N][2B Dactual][2B Error][1B 判定]），回 DC_IDLE。

### 关键决策与权衡

- **移动到位动态等待（关键防回归）**：U7 步进指令非阻塞（收到即回 OK，电机由 U7 后台 ISR 走完）。若移动发出后只延迟 100ms，电机未走完会重蹈 adc_calib 任务"回程指令被 U7 busy 拒"的覆辙。故严格分三层：①动态等待覆盖物理走完（1mm=206步≈412ms）→ ②100ms 稳定延迟 → ③等新报文读值。
- **方向 CCW**：回零顶到 IN1（CW 限位端点），移动必须 CCW 反向进入行程区，否则顶限位失步（2026-08-22 已确认）。
- **增量定位**：与旧流程一致，电机不回零点连续走（1mm→1.5mm→2mm 各走增量步）。
- **保留判定与 25B 返回**：符合用户确认，不改变命令协议格式。
- **设偏移0**：U4_SetOffset(0) 使 length 字段 = raw_length，确保读到的直径无历史偏移干扰。

## 实现注意

- **Flash 空间极紧（32KB）**：复用现有宏/函数（U7_Home、U4_SetOffset、DC_StepsForTarget），不引入新依赖。
- **busy 检查**：`DiamCalib_Start()` 沿用 `dc_phase!=0` 判定；CMD 0x0011 分发处已有 `deferred_cmd`/`app_state`/`MotorSeq_IsBusy`/`ADC_Calib_IsBusy` 冲突检查（app.c 中已对 ADC_CALIB 增加，DIAM 处需核对是否同样需补，保持与 0x0010 一致）。
- **失败路径**：HOME/ZERO/SETOFFSET/MOVE 任一失败→直接 DC_DONE 返回全 FAIL（复用现有 allpass 逻辑，result[0]=0）。
- **日志**：不新增调试打印（省 Flash）。

## 架构设计

沿用现有非阻塞状态机架构，模块职责不变：

- `diam_calib.c`：校准编排（重写内部状态机）
- `protocol_u4.c`：U4_ZeroSensor / U4_SetOffset 已存在，直接复用
- `protocol_u7.c`：U7_Home / U7_MotorStep 已存在，直接复用
- `app.c`：CMD 0x0011 分发调用 DiamCalib_Start()，核对 busy 冲突检查一致性
- `diam_calib.h`：新增读前延迟宏，更新方向/流程注释
