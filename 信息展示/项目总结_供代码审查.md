# U1-U7-U4 多板测量治具系统 — 项目总结（供代码审查）

> 生成日期: 2026-08-17
> 用途: 供其他 AI 或工程师快速理解项目，进行代码审查

## 一、项目概述

三块 STM32 组成一个**线径测量治具系统**，用于生产/校准场景：

| 板 | 芯片 | 角色 |
|----|------|------|
| **U1** | STM32F103C6（32KB Flash，LQFP48）| 治具主控：PC 通信、固件烧录、电机调度、ADC 采集 |
| **U7** | STM32F103C6 | 电机板：TMC2209 驱动步进电机 |
| **U4** | STM32G031G8U6 | 测径板（DUT）：VCP1615 双通道线径传感器 + AMS5600 角度传感器 |

工作流程：上位机(PC)通过 USB 与 U1 通信 → U1 控制 U7 电机移动测量机构 → U4 实时测量线径并通过报文流上报 → U1 汇总/校验/回传 PC。

## 二、硬件连接

- **PC ↔ U1**：USB CDC（PA11/PA12），速率 460800 8N1
- **U1 ↔ U4**：USART2（PA2=TX→U4 RX, PA3=RX←U4 TX），运行时 115200 8N1，ISP 时 115200 8E1
- **U1 ↔ U7**：USART1（PA9/PA10），115200
- **U1 SPI Flash**：GD25Q128（16MB），PA4/PA5/PA6/PA7 + PB10(HOLD)/PB11(WP)
- **U1 ADC**：PB0/PB1/PA0/PA1 作 ADC 输入（原 OUT0/1/4/5 改用途），经 U2/U5 运放采测试点 ADC0~ADC3
- **U1 控制**：PA8→U4 BOOT0、PB15→U4 NRST、PB3→U7_EN（注：U7 实际由 USB 直供，U7_EN 不参与供电）
- **U4 传感器**：PA4/PA5/PA6 接 VCP1615/AMS5600

## 三、通信协议（注意 CRC 字节序不一致）

### 3.1 PC↔U1（manager 协议）
- 帧：`A5 5B | CMD(2B) | SEQ(2B) | LEN(2B) | DATA | CRC16(2B)`
- **CRC 高字节在前**（big-endian）
- 命令：0x0004 查U1版本、0x0008 查U7版本、0x0009-0x000B 固件上传、0x000C 查固件版本(Flash)、0x000D 查U4版本、0x0010 ADC极值校准、0x0011 测径精度校准、0x0014 ADC结果事件、0x0020 查ADC、0x0024 SN上报、0x002B 设U4报文周期
- 治具测试命令：0x0111 PING、0x0112 PROGRAM（烧U4）、0x0113 TEST_U4、0x0114 TEST_U7、0x0115 TEST_ALL

### 3.2 U1↔U4（★关键坑）
- 帧：`A5 5B | CMD(1B) | SEQ(2B) | LEN(2B) | DATA | CRC16(2B)`
- **CRC 低字节在前**（MODBUS RTU 标准）← 与 U1↔U7 相反，是历史 bug 根源
- 命令：0x10 归零、0x11-0x13 校准开始/完成/取消、0x14 读Flash参数、0x15 保存参数、0x16 恢复出厂、0x17 设偏移、0x18 设报文周期、0x20 AMS清零、0x30 报文流、0x50 查版本、0x34 读全部ADC（固件方未实现）
- 报文流 0x30（24B ccd_data_t）：length/raw_length/position/vo1/vo2/min_vo1/max_vo1/min_vo2/max_vo2/angle_acc/ams_adc

### 3.3 U1↔U7
- **CRC 高字节在前**；命令 0x28 读ADC、电机步进/停止、自检、版本等

## 四、U1 固件架构（`U1/U1project/`）

| 文件 | 职责 |
|------|------|
| `Core/Src/app.c` | 主状态机、命令分发、TEST/PROGRAM 流程 |
| `Core/Src/protocol_frame.c` | PC↔U1 帧封装/解析（高字节CRC）+ `Frame_Build_1B_LE`/`Frame_Parse_1B_LE`（低字节CRC，U1↔U4 专用）|
| `Core/Src/protocol_u4.c` | U4 协议非阻塞会话 + 报文流解析 |
| `Core/Src/protocol_u7.c` | U7 协议非阻塞会话 |
| `Core/Src/isp_programmer.c` | G0 bootloader ISP 烧录（0x7F同步/0x44擦除/0x31写/0x11读/0x21跳转）|
| `Core/Src/fw_upload.c` | SPI Flash 双槽固件上传 |
| `Core/Src/adc_consistency.c` | 三芯片 ADC 一致性校验 |
| `Core/Src/adc_calib.c` | ADC 极值校准状态机 |
| `Core/Src/diam_calib.c` | 测径精度校准状态机 |
| `Core/Src/bsp_uart.c` | UART FIFO + 8N1/8E1 动态切换 `U4_UART_SetMode()` |
| `Core/Src/bsp_adc.c` | ADC 驱动 + VREFINT 校准 VDDA |
| `Core/Src/sn_report.c` | UID 读取 + SN 上报 |

**Flash 布局**：SPI Flash slot0@0x10000(Bootloader)、slot1@0x20000(App)，各64KB，8字节头`[4B大小LE][3B版本][1B标志0xA5]`。U4 固件固定偏移：Bootloader@0x08000000、App@0x08005000。

## 五、关键修复历程（供审查关注）

1. **U1↔U4 CRC 字节序**：U1 原按高字节先，U4 用 MODBUS 低字节先 → 所有 U4 命令被拒（表现为"U4 不应答"）。新增 `Frame_Build_1B_LE`/`Frame_Parse_1B_LE` 解决
2. **8N1/8E1 切换**：U4 App 用 8N1、G0 bootloader 用 8E1，动态切换
3. **ISP_ReadMemory 修复**：补 `(N-1)^0xFF` 校验字节 + 消费 ACK（否则 UID 读错/移位）
4. **App 偏移修正**：固定 0x08005000（不能用 bootloader bin 大小推算）
5. **BOOT0 复位时序**：烧录后拉低 BOOT0 + 复位再进 App
6. **Flash 空间**：32KB 极紧（-Os），已删 0x31/0x33/0x35/0x36、IAP 系列、诊断命令（0x0025-0x002A）腾空间
7. **2026-08-14 数据源修正**：ADC 一致性校验 + 极值校准的 U4 数据改从 0x30 报文流取（因 0x34 未实现）

## 六、测试状态（截至 2026-08-17）

### ✅ 已验证
- U1↔U4 协议全通，TEST_U4 两次全 PASS（0x10-0x20 八命令）
- U4 版本 v1.3.1、报文流正常（50ms）、设周期 200ms 生效
- PROGRAM 烧录 + UID/SN 上报成功
- U1 本地 ADC 4 通道正常、QUERY_ADC target=1 正常
- 一致性校验：U4 数据已进入比对（实测确认），U1 vs U7 同测试点一致（差 1LSB）

### ⛔ 待硬件/待固件
- **0x34 读全部ADC**：固件方未实现，QUERY_ADC target=4 优雅失败（返回全0）
- **0x0011 测径精度校准**：协议通但**测量台未装** → 全 FAIL（U4 length 恒 900um 基线）
- **0x0010 极值校准**：数据源已改对，但裸电机无真实摆幅（~60LSB 仅为振动/干扰）

### ⚠️ 已知问题
- 版本标签不一致（SPI Flash 头 v1.2.3 vs U4 内部 v1.3.1）——上传时 FW_START 版本填错
- U4 vo1/vo2 存在 ~60LSB 周期振荡（疑似电机振动或 EMI，待确认）
- U1 的 ADC0/ADC1 测试点与 U4 vo1/vo2 是否同源未确认（若分接自 VCP1615，则 U1 读也等效）

## 七、审查关注点建议

1. 非阻塞协议会话的重入/超时/重试逻辑（protocol_u4.c / protocol_u7.c）
2. CRC 字节序在三个协议间的不一致是否有遗漏
3. 32KB Flash 空间优化是否还有隐患（已删命令是否影响功能）
4. 报文流解析与命令会话的并发（u4_report_fresh 消费冲突）
5. ISP 烧录时序与 G0 bootloader 的边界（8 字节对齐、校验）
6. ADC 校准状态机的电机到位时序
